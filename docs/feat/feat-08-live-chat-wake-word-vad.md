# Feat-08: Live 实时语音聊天（唤醒词 + VAD + 浅休眠）

> 更新日期：2026-04-08
> 来源：用户需求
> 优先级：P0

## 1. 功能概述

### 1.1 背景

VAD（语音活动检测）流程已可用。当前系统缺少端到端的"实时对话"体验：用户需要一种自然的方式触发对话（唤醒词），依赖 VAD 判断说话结束后自动提交至 ASR→LLM→TTS 处理管道，并在长时间无交互时自动降低功耗（浅休眠），等待下次唤醒。

### 1.2 目标

- 提供基于唤醒词触发的实时语音聊天能力
- 利用 ESP32 端 VADNet 在设备本地判断用户是否完成说话，静音段不经 BLE 传输，仅将有效语音帧发送至服务端
- 在 30 秒无输入/输出时自动进入浅休眠，降低功耗，等待唤醒词再次激活

### 1.3 非目标

- 不涉及唤醒词模型的训练或替换（使用乐鑫官方 `wn9_jarvis` 模型，唤醒词为 "Jarvis"）
- feat-07 的"唤醒后手动录音"逻辑由本 feat 接管并替换；feat-07 仅保留唤醒词检测能力，检测到唤醒词后直接进入本 feat 的 live 聊天流程，不再走按键录音分支
- 不支持多轮上下文的持久化存储（本期仅保证会话内上下文）
- 不涉及 BLE 固件侧的功耗优化（浅休眠仅指服务端/App 侧状态切换）

## 2. 用户场景

### 场景 1: 唤醒词触发对话

- **角色**：佩戴设备的用户
- **触发**：用户说出唤醒词 "Jarvis"
- **流程**：
  1. 设备检测到唤醒词，进入监听状态
  2. 用户自然说话，VAD 实时检测语音活动
  3. VAD 判断用户停止说话后，自动将本段音频提交至 ASR→LLM→TTS 管道
  4. TTS 语音回复播放给用户
  5. 播放完毕后继续监听，等待用户下一句话或超时进入浅休眠
- **结果**：用户完成一轮自然语音对话，无需手动操作

### 场景 2: 休眠与再唤醒

- **角色**：佩戴设备但暂时不说话的用户
- **触发**：连续 5 分钟内既无用户语音输入，也无 TTS 音频输出
- **流程**：
  1. 系统检测到 5 分钟空闲，iOS 断开 WebSocket，释放后台网络资源
  2. ESP32 持续保留唤醒词检测能力
  3. 用户说出唤醒词，iOS 重建 WebSocket 连接，开始全新对话
- **结果**：长时间闲置自动降低 iOS 电池消耗，唤醒后约 200-500ms 重连延迟

### 场景 3: VAD 驱动的多句连续对话

- **角色**：进行多轮问答的用户
- **触发**：唤醒词激活后，用户连续说多句话
- **流程**：
  1. 每次用户停顿，VAD 判断是否为句末停顿（区分自然停顿与说话结束）
  2. 确认句末后自动提交，TTS 回复
  3. 30 秒计时在每次有效输入或输出时重置
- **结果**：支持流畅的多轮连续对话体验

### 场景 4: TTS 播放中打断

- **角色**：不想听完回复、想直接追问的用户
- **触发**：TTS 正在播放时，用户开口说话（VADNet 检测到语音活动）
- **流程**：
  1. VADNet 检测到新的语音活动，iOS 立即停止 TTS 音频播放
  2. 向 Pipecat 发送打断信号，取消当前 LLM/TTS 任务
  3. 用户说完后，VADNet 检测句末，正常提交至 ASR→LLM→TTS 管道
  4. 30 秒空闲计时器重置
- **结果**：用户可随时打断 TTS，对话更自然流畅；不需要等待回复说完再说话

## 3. 验收标准

### 功能验收

- [ ] 说出唤醒词后，设备在 1 秒内进入监听状态（有可感知的状态反馈）
- [ ] VAD 检测到语音结束后，自动触发 ASR→LLM→TTS 管道，无需用户手动操作
- [ ] 连续 5 分钟无有效语音输入且无 TTS 输出时，iOS 断开 WebSocket 进入休眠
- [ ] 休眠状态下，唤醒词检测功能仍然有效
- [ ] 休眠唤醒后，重新建立 WebSocket 连接，开始全新对话
- [ ] 每次有效语音输入或 TTS 输出，30 秒空闲计时器重置
- [ ] TTS 播放中用户开口说话，TTS 立即停止，进入新一轮 ASR→LLM→TTS 流程

### 非功能验收

- [ ] 性能：从 VAD 检测到句末到 ASR 开始处理的延迟 ≤ 300ms
- [ ] 性能：唤醒词响应延迟 ≤ 500ms（从说出唤醒词到进入监听状态）
- [ ] 稳定性：连续对话 10 分钟内无异常退出或状态卡死
- [ ] 兼容：与现有 feat-07 唤醒词检测模块无冲突

## 4. 约束条件

- **依赖 feat-07**：唤醒词检测能力由 feat-07 提供，本 feat 复用其接口，不修改唤醒词模型
- **ESP32 VADNet**：使用乐鑫 AFE 内置的 VADNet 模型（`vad_init = true`），在设备端本地判断句末；服务端（Pipecat）不再承担 VAD 职责，仅执行 ASR→LLM→TTS
- **BLE 带宽约束**：音频数据通过 BLE L2CAP 传输，实时对话依赖稳定的 BLE 连接
- **休眠策略**：5 分钟空闲后直接断开 WebSocket，不设中间浅休眠状态；ESP32 固件始终保持唤醒词监听，不进入硬件深度睡眠
- **5 分钟阈值**：初始值，后续可根据电池数据调整

## 5. 依赖关系

| 依赖模块 | 类型 | 说明 |
|----------|------|------|
| feat-07 唤醒词检测（wn9_jarvis） | 前置依赖 | 提供 "Jarvis" 唤醒词触发事件；唤醒后录音逻辑由本 feat 接管，feat-07 按键录音分支废弃 |
| ESP32 AFE VADNet | 前置依赖 | 设备端本地 VAD，判断句末；替代服务端 VAD |
| ASR→LLM→TTS 管道 | 前置依赖 | 已有管道，本 feat 负责正确触发 |
| Pipecat 后端 | 协作 | 管道状态管理、浅休眠逻辑 |
| iOS BLEManager | 协作 | 传递唤醒状态、浅休眠控制信号 |
