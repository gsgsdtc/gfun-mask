# Feat-07: 唤醒词触发语音录制

> 更新日期：2026-03-15
> 来源：用户需求（手动录入）
> 优先级：高

## 1. 功能概述

### 1.1 背景

当前 VoiceMask 系统需要用户手动操作才能开始语音交互，缺乏免提的自然唤醒能力。作为可穿戴 AI 语音助理，用户在佩戴设备时通常无法方便地使用触摸或按键操作，需要一种免触发的启动方式。

### 1.2 目标

- 支持通过预设唤醒词激活设备，无需手动按键
- 检测到唤醒词后自动开启麦克风录音
- 用户可通过手动操作（如按键或语音命令）结束本次录音会话

### 1.3 非目标

- 本期不支持自定义唤醒词（唤醒词固定为 "Jarvis"）
- 本期不支持多唤醒词并存
- 不涉及唤醒词的在线训练或个性化适配

---

## 2. 用户场景

### 场景 1: 免提语音交互

- **角色**：佩戴 VoiceMask 设备的用户
- **触发**：用户说出唤醒词 "Jarvis"
- **流程**：
  1. 设备持续监听环境音频，等待唤醒词
  2. 检测到唤醒词后，设备给出反馈（指示灯/提示音等），麦克风自动进入录音状态
  3. 用户说出指令或问题
  4. 用户按下设备按键结束录音，设备将录制内容发送至处理管道
- **结果**：用户完成一次完整的语音交互，无需触碰设备

### 场景 2: 手动结束录音

- **角色**：正在进行语音输入的用户
- **触发**：用户完成语音输入，希望提交内容
- **流程**：
  1. 用户完成说话
  2. 用户按下设备按键
  3. 设备停止录音，将音频数据提交至后续 STT/LLM/TTS 管道
- **结果**：录音结束，语音内容被送入处理流程

---

## 3. 验收标准

### 功能验收

- [ ] 设备在待机状态下持续监听，检测到唤醒词后自动开始录音
- [ ] 唤醒响应时延 ≤ 500ms（从唤醒词结束到录音开始）
- [ ] 唤醒成功后，设备播放提示音给予反馈
- [ ] 用户按下设备按键后 ≤ 200ms 内停止录音
- [ ] 手动结束后，录音数据能正常进入后续处理管道
- [ ] 未检测到唤醒词时，麦克风不进入录音状态（不误触发）

### 非功能验收

- [ ] 性能：待机监听对设备功耗的影响在可接受范围内（待补充指标）
- [ ] 安全：非唤醒状态下，设备不持续上传音频数据
- [ ] 兼容：唤醒功能不影响现有 BLE L2CAP 音频传输流程

---

## 4. 约束条件

- 唤醒词固定为 **"Jarvis"**，使用 ESP-SR WakeNet9 内置模型（`wn9_jarvis_tts`），无需训练
- 唤醒词检测框架为 **ESP-SR**（Espressif 官方组件），通过 `idf_component_manager` 集成
- 唤醒词检测在 ESP32-S3 本地离线运行，不依赖网络连接
- ESP32-S3 Box Lite 硬件资源需能同时支撑 WakeNet9 运行与音频采集
- 唤醒词检测与音频采集/编码流程需能协同工作，避免资源争用
- 依赖 feat-02（ESP32 音频采集与 Opus 编码）提供的音频管道能力
